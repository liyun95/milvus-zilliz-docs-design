# 06 上游变化的发现与影响报告

milvus-docs 合并新提交后，Cloud 要自动得知，并自己决定是否采用、何时采用。本篇定义怎样发现上游变化、怎样发起上游更新 PR，以及 PR 中给审核人看的影响报告。

**参与方**：milvus-docs（新提交）、zdoc 中的自动任务（发现、生成、发起 PR）、Cloud 文档工程师（审核）。

**状态**：待定义。下面先列出要定义的事项，以及已经确定的约定。

## 要定义

| 事项 | 说明 | 来自 |
|---|---|---|
| 触发方式 | 定时还是事件触发 | — |
| 执行身份 | 自动任务以什么身份运行；社区 PR 不提供 Cloud 凭据 | — |
| 重复事件 | 短时间内多个提交怎样合并为一个 PR | — |
| 失败处理 | 失败重试与手动重跑 | — |
| PR 内容 | lock 变化、生成差异、预览与影响报告的格式 | [01](./01-named-blocks.md#命名块清单与块的类型) |
| 跨页一起采用 | 同一 commit 中互相依赖的页面（例如一页改了标题，另一页改了指向它的链接）放进同一个上游更新 PR，避免 UAT 上只更新了其中一页 | [04](./04-channels-and-lock.md#标题改名与锚点) |
| 整页上线与下线的触发 | 新接入页面功能尚未上线、或要下线一页时，作者怎样在 PR 中说明，工具怎样写入 lock 的 `none` | [04](./04-channels-and-lock.md#整页上线与下线) |

## 已经确定的约定

![上游变化成为 Cloud 上游更新 PR 的过程：milvus-docs 的 PR 经 CI 检查后合并；zdoc 工具发现新提交，固定 commit 重新生成并比较变化，在 zdoc 发起附 lock、生成差异和影响报告的上游更新 PR；命名块被删除或改名时阻止更新，旧版本继续有效。Cloud 文档工程师审核：修改则回到源文件，暂缓则保持旧版本，合并则更新 lock 的 next，新版本先在 UAT 可见；Cloud 发布时把 current 改为 next，Prod 采用新版本。](../assets/upgrade-pr-flow.png)

图 1 · 上游变化怎样成为 Cloud 的上游更新 PR

- **上游更新 PR 就是一个普通的 zdoc PR。** PR 中更新 lock 的 `next`，附生成结果的差异、预览和影响报告；审核与批准沿用 GitHub PR，不另建审批记录。lock 由工具生成，写作者不手填 hash。
- **跟踪分支只用于发现变化。** 正式生成始终使用 lock 中固定的 commit（见 [04](./04-channels-and-lock.md#写入与提升)）。

不同的上游变化，工具应有的行为：

| 上游变化 | 行为 |
|---|---|
| 新增合法的命名块 | 自动进入命名块清单，不自动更新或发布 |
| 移动块或修改标题，ID 不变 | 身份保持，检查内容和上下文变化 |
| 块改名或删除 | 引用它的页面不能更新，旧版本继续有效，需要显式迁移 |
| 被 Cloud 替换的原文发生变化 | 即使 Cloud 输出不变，也提示复核 |
| 被 Cloud 按行定位的代码行被修改 | 匹配失败，引用它的页面不能更新，旧版本继续有效 |
| Cloud 规则只在 `next` 上失效 | 上游更新 PR 失败并指出通道，`current` 与 Prod 不受影响 |
| 类型、上下文或语言变化 | 检查兼容性，不静默组装 |
| 只新增标记，正文未变 | 更新身份与依赖，不触发重译 |
| 标题改名 | 报告改名与受影响的链接，处理见 [04](./04-channels-and-lock.md#标题改名与锚点) |

影响报告按页汇总：代码组报告完整代码组的上下文，Markdown 块报告页面上下文，按行定位的规则随所在代码组报告。摘要只能发现变化，不能判断语义是否一致，首期提示可以保守。

## 验收

- **T05**：被替换的原文变化仍然提示；上游变化只生成 PR，不自动采用；PR 合并前的生成结果不进入正式发布。
- **T12**：完整旅程中采用或拒绝上游更新。

# 首期实施计划

本文面向实施者与评审人，回答首期做什么、按什么顺序做、怎样算完成。为什么改见[方案总览](./proposal.md)，系统怎样搭建见[架构设计](./architecture.md)。

状态：待工程评估与实施。两篇本地样例已可运行；生产的共享内容接入、md2md 新入口和发布保护尚未实现。具体人员、工作量和日期由评审确定。

## 1. 目标与完成定义

**首期完成，意味着批准的试点页已经从 Git 来源生成并上线，并通过后续更新、翻译和恢复的验证。** 只在本地生成 MDX，或只拿到预览，都只完成了一部分。切换后，共享原文改 milvus-docs，Cloud 的配置、变量和差异改 zdoc，旧的飞书任务不能再覆盖或删除这些页面。

首期分两步：

| 阶段 | 试点页 | 完成标志 |
|---|---|---|
| **1a 整篇复用跑通** | Delete Entities | 经真实 zdoc 生成，UAT 预览内容完整；候选没有生产写权限；Milvus 发布回归通过 |
| **1b 差异、升级与切换** | Filtered Search、OpenAI | 差异正确生成；上游变化以升级 PR 采用；批准的试点页切换上线，并通过更新、翻译与恢复验证 |

建议年底前完成 1a 并启动 1b。

**首期不做：** 代码子区域替换（行级差异用产品行指令，差异多时替换整个语言项）、selector、move/copy、变换链、条件模板语言、按业务定义专门的操作、独立的 registry 服务或内容分发链、完整归档、独立编排多个共享片段的页面、SDK Reference、全量迁移，以及 Cloud 独有页的迁移。

## 2. 任务全景

![首期任务与依赖：五条泳道分别是内容、zdoc 生成、md2md、zdoc 发布和运行条件。1a 中，Delete Entities 内容对齐后，zdoc 实现获取、定位、变量与 MDX 生成并接入 stage 与 UAT 预览；md2md 的预处理入口发版后 zdoc 才能真实集成；发布侧完成 Git 来源接入设计。1b 中，Filtered Search 与 OpenAI 内容对齐后，zdoc 实现差异与过滤、升级 PR；Milvus 侧过滤上线后才能合并带指令的原文；发布侧完成混源与同批激活、翻译与恢复，在文档负责人审核后切换试点页。运行条件从第一天开始核实，切换前必须解决。](./assets/phase-dependencies.png)

图 1 · 首期任务与依赖
- **关键路径在 md2md 发版。** zdoc 可以先用共同的测试样例开发，但真实集成要等 md2md 新入口发版并固定版本。Milvus CI 目前安装 npm 包时没有固定版本，需要一并处理。
- **发布接入可以提前开始。** Git 来源接入的设计在 1a 就可以做，与生成能力并行；但联合验证必须使用真实生成结果，替代输入只能帮助开发。
- **带指令的原文要等 Milvus 侧过滤上线。** 否则 Cloud 的代码行会出现在 Milvus 站点上。
- **运行条件不能等到最后。** Jenkins、分支权限和资源保留从第一天开始核实，阻碍持续跟踪；本地样例通过不代表这些条件已经具备。

每个仓库的能力属于哪一类：

- **沿用**：Markdown 与 `Variables.json` 写法、Cloud Tabs 等组件、MDX 与链接校验、Docusaurus 构建、产品代码变体、Current / Next 通道、翻译机制。仍需用共享输入验证。
- **扩展**：md2md 的调用入口；zdoc 的来源模型、Guides 组装、缓存、页面归属与发布恢复。
- **新增**：命名块扫描与 registry、差异变换与通道包裹、Milvus Markdown 到 Cloud MDX 的适配、依赖索引与升级 PR。

影响估算的三个边界：现有 local source 没有 Git 锁定与命名块消费；LarkDocWriter 接收飞书数据，不能解析 Milvus Markdown；发布保护和旧飞书任务的归属检查都要扩展到 Git 输入。[复用审计](../research/md2md-zdoc-reuse-audit.md)

## 4. 1a：整篇复用跑通

**任务**

1. **内容**：Delete Entities 两端正文对齐，确定共同修订与产品差异，产品值改为变量；审核 SDK 适用性。
2. **md2md**：实现只做预处理的入口，包括受控读取、依赖报告与错误检查；发版，并在 Milvus CI 中固定版本。
3. **zdoc 生成**：按固定 commit 获取原文，定位命名块并生成 registry，调用 md2md 展开变量，生成 Tabs 与 MDX。
4. **zdoc 生成**：接入现有 stage 与 UAT 预览；候选任务不具备生产写权限。
5. **zdoc 发布**：确定 Git 来源接入方式：生成结果、资源、来源与依赖记录的交接格式，以及生效配置的存储位置。
6. **运行条件**：开始核实 Jenkins 接线、分支权限、图片与镜像保留、`Release Channel` 迁移位置，记录责任人。

**完成标准**

- 【T01】注册与扫描：无命名块的整页可以注册；重复、空块、交叉、伪标记和非法嵌套都报错。
- 【T02】md2md 变量入口：显式产品绑定；与原有作用域兼容；缺失变量报错；两个产品并行生成时不串值；不运行 Milvus 站点插件。
- 【T03】include 与依赖：嵌套与重复引用可以追踪；循环、越界、符号链接、深度或体积超限都失败。
- 【T06】MDX、路由与资源：Tabs 可切换、语言完整；锚点、导航、链接、图片和编辑入口正确；缺图、图片字节变化或未知语法都失败。
- 【T11】Milvus 回归：新旧 md2md 默认行为兼容；真实 goover 构建通过，没有标记泄漏或内容丢失。
- 【T12，候选部分】没有权限的候选任务不能写生产。
- 对照批准的完整基线核验正文、章节、语言、代码、图片和导航；不能只统计 Tab 数。

## 5. 1b：差异、升级与切换

**任务**

1. **内容**：Filtered Search 与 OpenAI 两端对齐（OpenAI 先补齐语言与步骤），加命名块和代码行指令。等 Milvus 侧过滤上线后再合并。
2. **md2md**：代码行产品过滤与命名块清理，Milvus 站点只保留 `milvus` 行。
3. **zdoc 生成**：add / replace / remove；产品过滤器接入 Git 输入；把命名块包进 `<NextChannel>`。
4. **zdoc 生成**：依赖索引、影响报告与升级 PR；按[架构设计第 3 节](./architecture.md#3-上游变化与升级-pr)的规则处理各类上游变化。
5. **zdoc 发布**：页级混源与同批激活；旧飞书任务隔离；CI 重新生成比对；过滤、通道、翻译与恢复接入。
6. **切换**：核对最新飞书修订，文档负责人审核后切换试点页，更新编辑入口；记录验证结果与后续迁移条件。

**完成标准**

- 【T01】命名块改名或删除时，引用它的页面不能升级，旧版本继续有效。
- 【T04】内容变换与行级指令：目标存在性、类型、语言和冲突检查；通道包裹输出正确；多语言内容完整。以 OpenAI 的凭证参数为真实用例，在每种语言中验证 Cloud 只保留 `zilliz` 行、Milvus 只保留 `milvus` 行，两侧都不残留指令行或多余空行；语法错误、未闭合区域和未知目标都失败。
- 【T05】升级 PR：被替换的原文变化仍然提示；上游变化只生成 PR，不自动采用；PR 合并前的生成结果不进入正式发布。
- 【T07】混源与切换：覆盖[架构设计图 4](./architecture.md#6-按页迁移与正式激活) 中的每一种情况——同步配置不激活；失败或取消保持原状；激活时配置、正文、导航、来源记录同批提交；等待期间基线变化不会覆盖新状态；部署失败不恢复飞书写权；飞书全量抓取、旧缓存、删除清单与恢复任务都不能改变已迁移页，未迁移页照常更新。
- 【T08】缓存：只有变量、片段、工具、资源或归属变化时也会重新检查，不会被飞书侧的“未变化”跳过；冷热构建结果一致，损坏的缓存不会发布旧结果。
- 【T09】翻译：以最终 Cloud 正文为输入，技术内容受保护；输出不变且已有有效译文时不重译；缺译文仍按原规则处理；英文、日文和中文的边界正确。
- 【T10】恢复：临时 artifact 不可用时，能从 Git 恢复或从固定输入重建；来源记录一致；缺源或缺资源时停止；镜像回滚不恢复飞书写权。
- 【T12】完整旅程：源 PR → 预览 → 审核 → 发布 → 升级或拒绝 → 恢复；手改生成文件，或连同来源记录一起改，都被拒绝。
- 【T13】过滤与通道：适用的正文与代码保留，不适用的被排除；Next 内容在 UAT 显示，在 Prod 和静态产物中不出现；Git 页面的整页通道在各语言译文中生效；未迁移飞书页的行为不变。
- **发布保护**：实际的 Git 服务端拒绝普通作者直接推送或强推正式生成分支；内容 PR 不能关闭核心检查。隔离环境的回放不能代替真实分支与凭据的权限核验。

T05、T07、T08、T11、T12 是上线阻断项；其他检查同样要在切换前完成。

## 6. 贯穿两个阶段的事项

### 6.1 待确认的接口

已确定的边界（共享源在 milvus-docs、组装在 zdoc、md2md 只提供预处理、按页切换）不变。以下接口在对应工作开始前确定，结果更新到架构设计或消费配置草案，不在本文维护第二份定义：

| 待确认项 | 要决定什么 | 最晚何时 |
|---|---|---|
| md2md 预处理 API | 调用参数、变量根目录与作用域、读取接口、依赖与错误的返回格式 | 1a 并行开发前；集成前完成发版 |
| 标记与指令的解析位置 | 命名块和产品行指令的解析、校验代码放在哪个仓库，Milvus CI 怎样复用，清理挂在哪个转换环节 | 1a；带标记的原文合并前 |
| 消费配置与通道 | 配置目录与字段、链接与图片映射、lock 粒度、跟踪的 Milvus 分支、整页通道与命名块包裹的写法（[草案](./consumption-schema.md)） | 目录在 1a 确定；通道写法在 1b 开发前 |
| 生成与发布的交接 | 生成结果、资源、来源和依赖记录的格式；Git 来源怎样进入现有来源模型；生效配置的存储与同批提交接口 | 1a 发布接入设计时 |
| 上游变化的发现 | 定时还是事件触发、执行身份、重复事件合并、失败重试与手动重跑；社区 PR 不提供 Cloud 凭据 | 1b 升级 PR 开发前 |
| lock 与影响报告 | 字段，以及它们怎样进入既有的发布和恢复数据 | 1b 升级 PR 开发前；恢复接线在切换前 |

每项确认都要留下接口约定、负责人和对应测试。未确认的接口不能按“直接复用”估为零工作量；若影响 md2md 发版或其他仓库，同步调整排期。

### 6.2 切换前必须核实的运行条件

- 候选页的拟议修订适用于目标产品和 SDK 版本，尤其是 Filtered Search 的 top-K 与 limit、结果说明和图片，以及各篇补齐的语言。
- 外部 Jenkins 的实际触发、审批、UAT / Prod 接线和运行版本。
- Git 分支保护、工作流身份和部署权限能否落实发布保护。
- 图片对象版本、保留策略和镜像回滚窗口，只为确认的缺口补能力。
- 整页 `Release Channel` 从飞书多维表格迁到 Git 的位置，以及译文的传递方式。
- 产品过滤的实际规则、翻译开关、语言发布契约、导航与其他飞书依赖的运行配置。

### 6.3 测试方式

- **沿用现有测试体系**：md2md 用 Jest，zdoc 用 Node、Vitest 与 Playwright，不另建测试平台。新增路径登记到既有的 code-to-test matrix。
- **执行顺序**：安装固定依赖 → 单元、兼容与契约测试 → 按变更矩阵检查 → 共享链路的完整回放 → 真实 artifact 隔离回放 → 必要的站点构建与浏览器检查 → 实际权限与恢复验证。
- **内容核验**：对照批准的完整基线检查正文、章节、语言、代码、前提、图片和导航。任何删减或语言合并都要有明确的内容决定；语法检查不能证明 SDK 行为，执行请求时使用获准的测试环境。
- **性能与审核负担**：记录冷热构建、单块修改、仅 Cloud 输入修改和无关源修改时的获取次数、耗时、内存与队列等待；可以用 1 / 10 / 100 页的合成规模测试扩展性，但不据此承诺生产耗时。同时记录受影响页数和需要复核的页数，评估审核负担。

## 7. 当前证据：本地样例

本仓库的 Python 脚本只用来验证设计中的组装规则，不是写作者将来要用的工具，也不代表生产实现的工作量。

| 样例 | 已覆盖 | 尚需验证 |
|---|---|---|
| Delete Entities | 整篇引用、连接变量、三组七语言 Tabs、正文与章节保留 | 真实工具链与 SDK 适用性 |
| Filtered Search | 产品名与连接变量、两个命名代码组、CLI 补充；专门测试覆盖块和语言项的 add / replace / remove | 真实工具链与 SDK / CLI 适用性 |
| OpenAI | 尚无样例；两端差异已核对（[核验记录](../research/zdoc-variants-and-channels-audit.md#3-openai-页对照)） | 内容对齐、行级指令在两侧的过滤、真实工具链 |

两篇样例都检查了不支持的 schema、缺失输入和手改生成结果等错误；都没有调用真实的 md2md、Docusaurus 或生产发布，也没有实现跨仓升级、翻译和发布保护。

样例的共享原文经过本地整理，尚未合入上游。registry 中 `based_on_commit` 记录整理前的 Milvus 基线，`source_commit: null` 表示拟议原文还没有对应的上游提交；注册规则中的 `source.track` 只表达跟踪分支，脚本实际读取本地文件。正式接入时由工具把审核采用的原文锁定到实际 commit。

运行原型需要 Python 3.10+，在 `examples/delete-entities/` 或 `examples/filtered-search/` 目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r ../../requirements.txt

python -B build_example.py
python -B test_example.py
python -B build_example.py --check
```

`prepare_fixture.py` 会从固定证据重新准备输入并覆盖作者文件，不属于日常步骤。Delete Entities 的预期结果包含拟议补入的 Go APIKey；输出一致不等于 SDK 行为已经验证。

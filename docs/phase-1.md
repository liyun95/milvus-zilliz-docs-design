# 首期实施与验收方案

状态：待工程评估与实施。两篇本地样例已可运行，生产共享内容接入模块（provider）、md2md 新入口及正式发布保护尚未实现。本文件描述交付边界，不是上线完成报告。

## 1. 首期交付与完成边界

以 Filtered Search 和 Delete Entities 为候选，打通共享内容从 Milvus 源 PR 到 Cloud 消费、预览、审核、发布、翻译、升级与恢复的完整流程。实施遵循[架构约束](./architecture.md)，配置以[消费规范](./consumption-schema.md)为准。

**首期完成意味着批准的试点页已经切换到 Git 来源，并通过后续更新、翻译和恢复验证。** 本次评审确定验证候选与分工；正式切换的页面和顺序，在内容与工程验证通过后批准。本地生成 MDX 或获得预览只完成部分交付；切换后，共享原文在 milvus-docs 修改，Cloud 消费配置、变量和差异在 zdoc 修改，旧飞书任务不能再覆盖或删除迁移页。

| 范围 | 首期要求 |
|---|---|
| 共享来源 | 固定 milvus-docs 修订；最少文件注册规则、自动扫描命名块、生成 registry |
| 作者接口 | 整篇复用、Variables.json、统一 add/replace/remove；只为必要区域命名 |
| 多语言 | 保留完整 SDK/CLI 内容，按共用规则生成 Tabs；不要求 writer 重写组件包装 |
| 代码区域 | 支持必要的命名区域整体替换；明确 include 缩进契约，接入真实 md2md 并验证兼容性 |
| 内容过滤 | 保留既有产品/版本过滤规则，验证共享 Git 输入与未迁移飞书输入的适用内容均正确 |
| 采用与升级 | 固定输入、自动依赖索引、上游变更检测、候选 PR/预览、审核后采用 |
| 发布与迁移 | Git 与未迁移飞书页的混合来源、同批激活、生成结果保护、旧任务写入/删除隔离 |
| 翻译与恢复 | 沿用既有能力，新增输入接线与恢复范围；验证资源可获取 |

两篇样例没有真实代码结构替换需求，不人为添加差异来证明接口；代码区域替换仍是已确认的工程要求，需单独的针对性 fixture 和契约测试。当前原型不支持该项，也不支持多来源框架。独立章节编排保留为扩展路径，不能据此宣称首期本地样例已经覆盖。

固定 Git commit 决定采用哪一份源内容；产品/版本过滤决定哪些内容应在目标产品和版本中显示。首期保留并接入既有过滤规则，不新增条件模板语言；实际规则与运行配置在接入前核实。

首期不新增 selector、任意代码行插入/删除、move/copy、变换链、条件模板语言、每种业务一个 operation、独立 registry 服务、上游内容包分发链、完整归档或翻译平台。SDK Reference 和全量内容迁移不在首期范围。

## 2. 仓库改动与能力分工

### 2.1 哪些仓库需要改

主要改动在 milvus-docs、md2md 和 zdoc，工程主体在 zdoc。共享源从 md2md 的转换命令 goover 处理前的 milvus-docs 固定修订获取，在 zdoc 组装为 Cloud 正文；web-content 继续服务 Milvus 发布。

| 仓库 | 首期改动 | 交接与边界 |
|---|---|---|
| [milvus-docs](https://github.com/milvus-io/milvus-docs) | 审核共同内容和 SDK 适用性；引入必要变量、命名标记及源检查；接入兼容的固定工具版本 | 输出共享 Markdown、默认 Variables.json 和必要资源；Cloud 差异留在 zdoc。检查既有飞书导入任务，撤销其对已迁移共享原文的覆盖能力 |
| [md2md](https://github.com/zilliztech/md2md) | 提供独立的变量/include 预处理入口、受控读取、依赖报告、错误检查及约定的代码缩进处理；发版 | 提供通用预处理能力。保持 Milvus 旧入口兼容；共享命名块提取、产品差异和 Cloud MDX 适配由 zdoc 负责 |
| [zdoc](https://github.com/zilliztech/zdoc) | 新增共享获取与组装，扩展升级审核、页级来源、发布保护、翻译和恢复接入 | 消费固定共享源与本仓配置，生成 Cloud 正文；复用现有站点与发布链，详见 2.3 |
| [web-content](https://github.com/milvus-io/web-content)、[milvus.io](https://github.com/milvus-io/milvus.io) | 验证变量、标记及 md2md 改动后的 Milvus 发布回归 | 首期不计划增加共享消费能力；发现必要兼容改动时再纳入任务。web-content 中的 SDK Reference 原文不在本次范围 |
| 本设计仓库 | 维护方案、消费规范、样例和验证依据 | 不参与生产内容生成，不作为第三份正文权威 |

另有跨仓运行配置需要协调：Git 分支保护、工作流凭据、Jenkins 接线，以及图片和容器镜像的恢复条件。这些工作从实施开始就核实，由相关维护者落实，不能仅通过修改仓库内 YAML 假定完成。

### 2.2 哪些沿用、哪些扩展、哪些新增

“沿用”表示保留已有实现和约定，仍需验证共享输入；“扩展”表示修改现有接口或数据模型；“新增”表示目前核验范围内尚无完整实现，不要求所有基础算法重新编写。

| 分类 | 能力 | 首期需要做的事 |
|---|---|---|
| 沿用 | Markdown、Variables.json、md2md 变量与文件 include 写法 | 保持作者写法，验证产品绑定和原有作用域兼容 |
| 沿用 | Cloud Tabs 等组件、MDX/链接校验、Docusaurus 构建 | 复用展示与检查，验证共享内容的语言、章节、导航和资源完整性 |
| 沿用 | 既有产品/版本内容过滤 | 核实正文与代码的适用规则及配置，将 Git 生成正文接入相应处理；验证未迁移飞书页的过滤行为保持一致 |
| 沿用 | 翻译候选、语义单元、技术内容保护及批次机制 | 将最终 Cloud 正文接入既有输入，核实语言契约和实际开关 |
| 扩展 | md2md 调用入口 | 公开只做预处理的接口，补充依赖与错误报告；旧 Milvus 入口保持兼容 |
| 扩展 | zdoc 来源、Guides 组装、缓存、归属与发布恢复 | 增加 Git 输入身份、页级混源、生效配置及写入/删除校验；把共享输入纳入现有发布与恢复范围 |
| 新增 | 命名块扫描、registry 生成、统一 add/replace/remove | 按最少注册规则获取整页和必要块，校验稳定身份并应用 Cloud 差异 |
| 新增 | Milvus Markdown → Cloud MDX 适配 | 解析源多语言代码等结构，生成既有组件格式；补齐英文接入 |
| 新增 | 共享依赖、上游影响分析与升级候选 | 追踪固定源和消费输入，报告受影响页面，审核后采用新版本 |

三个边界影响工程估算：现有 local source 只提供本地内容接入基础，没有 Git 锁定与块消费；LarkDocWriter 接收飞书数据，不能直接解析 Milvus Markdown；现有发布保护需要扩展到 Git 输入，旧飞书任务的缓存、写入和删除也必须遵守迁移后的页面归属。

依据：[工具能力审计](../research/md2md-zdoc-reuse-audit.md)、[发布链核验](../research/current-publication-chains-audit.md)、[恢复核验](../research/recovery-capability-audit.md)。固定源码已核对，线上运行修订、Jenkins 外部配置和部分权限仍未核实。已有 Git、图片存储和镜像恢复能力优先复用，只补核实后的缺口。

### 2.3 zdoc 内部怎样拆分工作

以下是工作边界，具体模块目录和接口签名在第 6 节确认。

| 工作部分 | 输入与处理 | 交付给下一环节的结果 |
|---|---|---|
| A．生成候选正文 | 读取固定 Milvus 源、注册规则、消费配置、Cloud 变量和差异文件；扫描命名块，调用 md2md，应用增删替换，完成 MDX 与资源适配 | 可预览的 Cloud 正文，以及实际输入、来源、资源和依赖记录；候选任务无正式发布写权限 |
| B．管理采用与升级 | 使用 A 的依赖记录，比较已采用版本与上游候选；被替换原文变化仍提示复核；生成升级 PR、预览及输入版本锁定记录（lock） | 绑定最终输入的升级候选与审核结果；分支用于发现候选，正式生成使用固定 commit |
| C．接入发布与迁移 | 将候选接入现有内容暂存区（stage）、校验和串行发布；同批激活配置、正文和来源；隔离旧飞书任务；接入过滤、翻译与恢复 | 正式生成正文、来源/构建记录和明确编辑入口，交给既有站点部署；生成文件不作为编辑源，手动修改不能进入正式发布 |

A 解决“能否正确生成”，B 解决“上游更新后怎样维护”，C 解决“怎样成为正式发布来源”。三部分都属于首期；A 单独完成不构成迁移完成。

配置同步仅准备候选。通过审核与校验后，生效配置引用、正文、必要导航和来源/构建记录在同一个受控 `dev` 提交中落定，此时激活 Git 来源并撤销旧来源的页面写入权。站点构建与部署随后进行；部署失败按既有机制重试或回滚，编辑权威仍为 Git。首期完成还要求批准页面实际部署上线，并通过后续更新、翻译和恢复验证。

## 3. 实施顺序、依赖与交付物

### 3.1 里程碑

下表用于拆任务和安排集成，验收编号对应第 4 节。建议负责方表示需要参与的职能，具体人员、工作量和日期由评审分配。

| 阶段 | 仓库与建议负责方 | 交付物与依赖 | 阶段完成条件 |
|---|---|---|---|
| P1 内容与运行基线 | milvus-docs、zdoc 文档工程师；构建/运维维护者 | 两篇文章共同内容与真实差异清单、固定审核基线；并行核实运行版本、权限、翻译、资源与恢复条件 | 内容适用性经审核；运行阻碍和责任人已识别，未解决项有处理安排 |
| P2 基础接口与跨仓开发 | md2md、zdoc 工程维护者；Milvus CI 维护者 | 确认第 6 节中影响当前开发的接口；开发预处理入口、Git 获取与扫描；发布并固定集成所用工具版本 | md2md 新入口可调用，旧行为兼容；共享读取和注册可验证（T01–T03、T11 的相关检查） |
| P3 整篇复用接入 | zdoc 工程维护者、文档工程师 | 基于 P1 内容和 P2 接口，用 Delete Entities 走通固定源 → 变量绑定 → Tabs/MDX → 现有 stage 与预览 | 对照完整基线验证正文、代码、语言、路由和资源；候选不能写生产（T02、T06、T12 的候选部分） |
| P4 局部差异与上游升级 | zdoc 工程维护者；文档工程师审核 | 在 P3 上用 Filtered Search 验证命名代码组和 CLI 补充；补齐通用变换、依赖索引、影响报告与升级候选 | 真实页面及专用测试覆盖增删替换、代码区域和缩进；结构失效阻止升级，旧采用版本保持有效（T01、T03–T05、T08） |
| P5 正式链路集成验证 | zdoc 发布、站点与翻译维护者；构建/运维维护者 | 汇合 P3/P4；完成混源、同批激活、权限与产物校验、内容过滤、翻译和恢复集成 | 第 4 节适用检查通过，包括 T13 过滤回归；旧 Lark 任务不能覆盖迁移页，临时 artifact 不可用时仍可恢复所需状态 |
| P6 按页正式切换 | 文档负责人、zdoc 工程及发布维护者 | 依赖 P5；核对最新飞书修订，审核迁移 PR，切换批准的试点页并更新编辑入口 | 验证实际发布、后续源更新与采用、翻译及恢复；记录验证结果、维护责任与后续迁移条件 |

P3 先选择 Delete Entities，是为了用整篇复用验证最短生成路径；P4 再用 Filtered Search 验证产品名变量和局部补充。代码区域替换仍属首期，通过针对性测试样例验证；不人为增加真实文章的差异。

### 3.2 并行关系与排期依赖

- **内容与环境并行准备。** P1 的运行核验从第一阶段开始，阻碍持续跟踪到解决，不能等到 P5 才检查权限、Jenkins 或资源可恢复性。内容基线尚未批准时可以开发接口，但不能据此确认最终内容正确。
- **接口确定后并行开发。** P2 中 md2md 预处理与 zdoc 获取/扫描可以使用共同的输入输出测试样例分别开发；P3 的真实集成依赖 md2md 发版、固定依赖及兼容验证。当前源码审计发现 Milvus CI 安装未固定 npm 包版本，需要同时处理。
- **生成与发布接入可交叉进行。** C 部分的来源、缓存和发布改造可在交接接口确认后，与 P3/P4 并行；P5 必须使用真实生成结果完成联合验证。替代输入只能帮助开发，不能代替集成验收。
- **翻译与恢复及早接线。** 有稳定 Cloud 正文和来源身份后即可开展相关验证，不必等所有变换实现结束；完整验证和实际权限核实必须在 P6 切换前完成。
- **按依赖安排交付。** 跨仓接口确认、md2md 发版、源内容审核、zdoc 集成与运行权限均可能影响切换日期。评审应分别指定负责人、前置依赖、工作量和验收证据，不能用本地 Python 样例的开发量代替正式 Node 工程及跨仓协调的估算。

第 6 节的接口选择应在对应工作开始前确定，第 7 节的运行条件从 P1 开始核实；原型测试通过不解除这些依赖。

## 4. 验收矩阵

以下是必须落地的测试要求；“已有相邻能力”和“样例验证”不等于正式共享路径已通过。

| 编号 | 测试范围 | 关键成功与失败断言 |
|---|---|---|
| T01 | 注册与标记扫描 | 无块整页、新增和移动；重复/空块/交叉/伪标记、非法嵌套报错；改名/删除使旧消费升级失败 |
| T02 | 真实 md2md 变量入口 | 显式产品绑定、原有作用域兼容、空值/类型契约、缺失变量报错；并行两产品不串值；不运行 Milvus 展示插件 |
| T03 | include 与依赖闭包 | 嵌套/重复引用和多 token 实际读取可追踪；循环、越界、symlink、深度/体积超限失败；代码缩进逐字验证 |
| T04 | 内容变换 | add/replace/remove 目标存在性、类型、语言和冲突；父子同时替换拒绝；全部多语言内容保留；完整父代码校验 |
| T05 | 升级与审核绑定 | 被遮蔽原文变更仍提示；自动 hash 不是批准；伪造 PR/approved、审核后改输入、旧身份批准不能放行 |
| T06 | MDX、路由与资源 | 真实 Tabs 可切换，语言完整；锚点、导航、链接、图片及编辑入口正确；缺图/图片字节变更/未知语法失败 |
| T07 | 混源与来源切换 | Git 页和未迁移 Lark 页同批更新；候选同步不激活；提交前失败/取消保留原状态；来源、正文、导航和构建输入/输出记录（receipt）同批提交；提交后部署失败不恢复飞书写入权 |
| T08 | 缓存 | 仅变量/片段/工具/资源/归属变化即重新检查，不能被 Lark 无变化跳过；冷/热结果一致，损坏缓存不发布旧结果 |
| T09 | 翻译 | 最终 Cloud 正文作为输入，技术内容受保护；有有效译文且输出不变不重译；缺译文仍按原规则出候选；英文/日文及中文边界正确 |
| T10 | 恢复 | 临时 artifact 不可用时从 Git 恢复或固定输入重建；来源记录保持一致；缺源/资源停止；可信镜像回滚不恢复飞书双写 |
| T11 | Milvus 回归 | 新旧 md2md 默认行为兼容；标记不泄漏、不丢内容；允许的源修订另行审核；真实 goover 构建通过 |
| T12 | 作者到发布完整旅程 | 源 PR→预览→审核→发布→升级/拒绝→恢复；手改 MD 或连来源与摘要清单（manifest）一起改均拒绝；无权限候选不能写生产 |
| T13 | 产品/版本内容过滤 | 核实既有规则和目标配置；适用正文与代码保留，不适用内容在最终页面中排除；切换目标产品/版本时结果符合审核基线，固定同一源 commit 不能绕过过滤；Git 输入接入后未迁移飞书页的既有行为不变 |

T05、T07、T08、T11、T12 是上线阻断项；其他适用检查同样应在切换前完成，不能用“有验收文档”代替实测。

### 必须覆盖的切换中间状态

C0 表示当前已生效配置，C1 表示待审核采用的候选配置。

1. C1 配置已同步，但 C0 仍生效：旧来源照常更新，C1 只做候选。
2. C1 构建/检查失败或提交前取消：C0、旧正文与来源记录不变。
3. C1 获批且校验通过：在既有串行边界核对当前发布基线，同一个受控 dev 提交安装配置引用、正文、必要导航、来源与 receipt，同时激活新来源；站点部署在此后进行。
4. 等待期间基线变化：旧候选不能覆盖新状态。成功任务重试保持幂等，不恢复旧来源。
5. dev 提交成功、部署失败：走既有部署重试或镜像回滚，编辑权威仍为 Git。
6. Lark 强制全量、旧缓存、删除清单与恢复任务：均不能改变已迁移页，未迁移页仍能正常更新。

### 必须覆盖的代码缩进行为

使用真实 md2md 新入口，将源基础缩进四格的片段插入零/四/八格位置，逐字核对输出，保持内部层级、空行和源字节不变。重复引用不复用错误缩进；字典项等片段校验整个父 fence。同行代码、字符串内伪引用、混合 tab/空格、语言不匹配、可能改变多行字符串值时明确拒绝。普通 Markdown 引用及旧入口不受影响。

### 必须覆盖的发布保护

实际 Git 服务端拒绝普通作者直接推送/强推正式生成分支；候选工作流无正式写权限。干净重建发现手改 MD 和伪造 manifest；批准后换输入需重审；校验后替换 artifact 在交接/部署入口失败。内容 PR 不能同时关闭核心 gate。隔离 bare remote 回放不能替代真实分支与凭据权限核验。

## 5. 执行方式与当前证据

### 本地样例检查

本仓 Python 脚本用于验证设计中的有限格式组装，不是未来作者需要执行的生产工具。两篇样例的共享原文经过本地整理，尚未合入上游；注册规则中的 `source.track` 用于表达候选跟踪分支，脚本实际读取本地文件，不拉取该分支。

生成 registry 的 `based_on_commit` 记录整理前的 Milvus 基线；`source_commit: null` 表示当前拟议原文尚无对应的上游提交。正式接入应由工具将审核采用的原文锁定到实际 commit，不能把跟踪分支或原始基线当成采用版本。

| 验证材料 | 当前覆盖 | 尚需实现或验证 |
|---|---|---|
| Delete Entities | 整篇引用、两端连接变量、三组七语言 Tabs、正文与章节保留 | 真实工具链与 SDK 适用性 |
| Filtered Search | 产品和连接变量、两个命名代码组、CLI 补充；专用测试覆盖 Markdown 块与语言项的 add/replace/remove | 真实工具链与 SDK/CLI 适用性 |
| 代码内部命名区域 | 尚无本地实现 | 首期需另行实现区域整体替换、include 缩进处理，并用专用测试验证 |

两篇均检查不支持的 schema、缺失输入和手改生成结果等错误情况。实际覆盖以测试脚本为准；均未调用真实 md2md、Docusaurus 或生产发布，也未实现跨仓升级、翻译和发布保护。

如需检查原型，使用 Python 3.10+，在任一样例目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r ../../requirements.txt

python -B build_example.py
python -B test_example.py
python -B build_example.py --check
```

两篇目录分别为 `examples/delete-entities/` 和 `examples/filtered-search/`。`prepare_fixture.py` 用于从固定证据重新准备输入，会覆盖作者文件，不属于日常修改步骤。Delete Entities 的预期结果包含拟议补入的 Go APIKey；原始快照单独保留，输出一致不等于 SDK 行为已经验证。

### 生产实施验证

正式实现沿用 md2md 的 Jest 测试以及 zdoc 的 Node/Vitest/Playwright 体系，不另建测试平台。新增路径必须登记既有 code-to-test matrix；现有 UI coverage 范围不能充当共享模块覆盖证明。

执行顺序：安装各仓固定依赖 → 单元/兼容/契约测试 → 按变更矩阵运行检查 → 共享链路相关的完整 replay/workflow-policy → 隔离真实 artifact 回放 → 必要站点构建和浏览器检查 → 实际权限/恢复验证。具体命令和运行版本以实施 checkout 的既有配置为准。

对照批准的完整基线核验正文、章节、语言、代码、前提、图片和导航。任何删减、修订或语言合并应有明确内容决定，不能只统计 Tab 数。语法检查不能证明 SDK 产品行为；执行请求时使用获准的测试环境。

性能记录冷/热构建、单块修改、仅 Cloud 输入修改和无关源修改；观测获取/解析次数、耗时、内存与队列等待。可用 1/10/100 页合成规模测试扩展性，但不据此承诺生产耗时。记录受影响页数、输出未变但需复核页数和翻译候选数，评估审核负担。

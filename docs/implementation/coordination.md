# 裁决主会话与执行会话

2026-10-30 起采用。推动者已同意由一个主会话维护设计、todo、任务卡和审阅结论，各工作包在独立执行会话中完成。本地会话登记用于调度；对外进度以任务卡、PR 和 `reviews/` 下的固定版本审阅记录为准。

## 分工

| 角色 | 负责 | 交付 |
|---|---|---|
| 裁决主会话 | 需求、优先级、任务卡、跨任务接口、计划审阅、代码审阅结论、状态维护 | 版本明确的任务卡、裁决记录、验收结论 |
| 执行会话 | 核查当前代码、计划、实现、自测、修订 | 固定 commit 的改动和证据包 |
| 独立审阅者 | 按任务卡检查实现、测试和遗漏，必要时复现 | 带文件/行号、影响和修复要求的问题清单；不自行扩大范围 |
| 推动者 | 产品取舍和需要人决定的发布动作 | 具体决定；无需代为搬运常规交接信息 |

主会话可以读取执行会话、分发任务和发送审阅后的修订要求。执行会话完成当前阶段后写交接文件并结束该阶段，主会话通过读取或等待获取结果；不要求执行会话主动向其他 chat 发送消息。需要修订时继续原执行会话、原 PR。

## 阶段与裁决

1. **任务卡就绪**：写明目标、依赖、范围、验收、外部操作权限以及本次分发阶段。
2. **计划待审**：复杂任务先核查当前代码，列出精确改动路径、公共接口、测试矩阵和未决问题。主会话批准后才进入实现。
3. **实现中**：一个工作包一条执行线、一个独立工作树。超出范围或发现需求冲突时，交回主会话裁决；独立工作可继续。
4. **代码待审**：交付固定 head SHA。主会话组织独立审阅、检查设计符合性和必要验证，形成一份统一意见。
5. **修订中**：原执行会话修改同一 PR。主会话复核新 SHA 的增量以及受影响的验证；不沿用旧 SHA 的通过结论。
6. **开发完成**：约定的需求和测试满足，审阅无阻断项；合并状态单独记录。
7. **发布待验收 / 已验收**：记录实际 Fetch、Translation、部署 SHA 和网站结果。开发完成不意味着已经发布。

主会话批准计划或技术审阅，不代替仓库维护者要求的 PR review、分支保护或推动者保留的发布决定。审阅者发现问题，不直接在执行工作树中改代码。

## 每次分发必须写清

- 任务卡的路径、版本或文件摘要；设计基线和实现基线。
- 本次阶段：核查计划、实现或修订；停止点及交回方式。
- 可改路径、明确不做的事项、共享文件的归属。
- 验收要求、证据格式、分支和工作树规则。
- 外部动作权限。本轮新任务默认允许只读核查及任务范围内本地工作；提交、推送、建 PR、外部评论、触发工作流、改 Base、发布分别按分发指令授权，不从另一任务继承。

## 交接包

| 字段 | 内容 |
|---|---|
| 身份 | 工作包、任务卡版本、计划/代码交接阶段 |
| 版本 | 仓库、工作树、base SHA、head SHA、PR（若已有） |
| 范围 | 变更文件、需求编号、偏离任务卡之处及理由 |
| 验证 | 命令、退出状态、执行 checkout/SHA、通过/失败/跳过、证据路径 |
| 遗留 | 未决问题、风险、所需裁决、未执行的外部动作 |
| 状态 | git status；是否有其他人的改动；下一步建议 |

任务卡和裁决以仓库文件为依据，会话负责推进。主会话在审阅前重查远端状态；执行线不凭旧摘要判断是否已合并。批次内容工作已有执行会话时沿用原任务，不重复分派。详细规范沿用[实现指南](./README.md)。

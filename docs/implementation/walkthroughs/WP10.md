# WP10 走读：变换

**仓库**：zdoc　**上游 PR**：[zilliztech/zdoc#900](https://github.com/zilliztech/zdoc/pull/900)，2026-10-28 合并（[`a9aac9b66`](https://github.com/zilliztech/zdoc/commit/a9aac9b66aa21886717d2a76932752d3810d7d01)）；计划与审阅在 [liyun95/zdoc#13](https://github.com/liyun95/zdoc/pull/13)　**任务卡**：[WP10](../tasks/WP10-zdoc-transforms.md)

## 解决什么问题

WP8 之后，`page.yaml` 只能整页引用原文，`transforms` 写了也会被拒绝（“Nonempty transforms require WP10”）。Cloud 与 Milvus 不只差几个值时，比如一节只适用于 Milvus，就没法接入。WP10 让 `transforms` 可以用：对原文的命名块、代码组中的一种语言、一种语言中连续的几行，做增加、替换、删除（[产品需求场景 4](../../prd.md#场景-4写-cloud-的差异)）。

- 新内容来自页面目录中的 Cloud 内容文件，或配置中的 `content.lines`，与原文经过同样的处理：变量、片段、产品过滤、链接、站点适配、产品名检查。
- 任何一条变换不成立，这一页生成失败，合法的那几条也不执行。
- 没有 `transforms` 的页面，生成结果逐字节不变。
- Fetch 不用改：它调用的就是 `shared-docs build`。

## 一页经过的地方

变换插在读取之后、预处理之前，在**带命名块标记的原文**上执行。每个通道（`current`、`next`）各走一遍：

| 步骤 | 做什么 | 代码 |
|---|---|---|
| 1. 解析命名块 | 定位块、判断类型（Markdown 块还是代码组）和语言 | 现有的 `parseBlocks`、`inventoryBlocks` |
| 2. 校验 | 两个通道的全部变换先校验，任何一条不成立就报错，不执行 | `planTransforms` |
| 3. 执行 | 按块的起止行、代码组中的语言、定位行，插入或删去内容；新内容按定位行补上缩进 | `applyPlan` |
| 4. 去掉标记 | 删去 `<!-- doc:block:… -->` 行 | `stripMappedMarkers` |
| 5. 预处理 | 整页（包括插入的内容）调用 md2md 展开变量与片段，内容文件中的 `{{var.xxx}}` 因此取 Cloud 的值 | 现有的 `md2md.preprocess` |
| 6. 产品过滤 | `<include target="…">`、`<exclude target="…">`：Guides 按 `saas`、BYOC 按 `paas` 保留或删去 | `filterContent` |
| 7. 之后 | 链接、站点适配、Tabs、产品名检查，与没有变换的页面相同 | 不变 |

每一行都带着“来自哪个文件的第几行”，报错因此能指向 milvus-docs 原文、Cloud 内容文件，或 `page.yaml` 中的那一项。

## 文件地图

都在 zdoc 的 `packages/docs-tooling/src/shared-docs/` 中。新增的 `core/transforms/`，纯计算：

## 代码怎样工作

### 1. 三级目标

| 目标 | `add` | `replace` | `remove` |
|---|---|---|---|
| `block` | `content.file` + `position` | `content.file` | 只写目标 |
| `block` + `language` | `content.file`，不写 `position`；顺序交给 Tabs 规则 | `content.file` | 只写目标 |
| `block` + `language` + `lines` | `content.lines` + `position` | `content.lines` | 只写目标 |

- **语言名**按 `presentation/cloud-sdk-tabs.yaml` 的 `aliases` 归一，`cpp` 与 `c++` 是同一种语言。
- **代码行**：`lines` 是原文中连续的 1–5 行，比较时忽略行首缩进与行尾空格，在这种语言的代码中必须恰好出现一次。
- **删掉代码组中仅剩的一种语言**报 `TRANSFORM_TARGET_KIND`，提示改为删除整块。

### 2. 先全部校验，再执行

`planTransforms` 在两个通道的原文上校验所有目标，再统一执行。同一目标两条变换、范围相交、上下级重叠，报 `TRANSFORM_CONFLICT`；同一位置的多条 `add` 允许，按列表顺序输出。这样一页不会出现“前两条执行了、第三条失败”的中间状态（4-1）。

### 3. 行号对照与第二次预处理

插入内容后，后面阶段的行号与原文对不上。WP10 不自己实现变量与片段的展开，而是给每一行加上不可见的来源标记，再调用一次同一个 md2md 预处理，从结果中读出每一行来自哪里。第二次调用去掉标记后，必须与正常调用的结果逐字节相同，否则这一页失败。在 Fetch 中，这种内部错误只影响这一页：保留 dev 上现有的版本，其他页面照常发布（审阅时要求补的测试）。

### 4. Cloud 内容文件

| 可以用 | 不可以用 |
|---|---|
| 与 Milvus 原文相同的 Markdown 写法 | 命名块标记 |
| 变量、片段，取 Cloud 的值 | 手写的 `<Tabs>`、`<TabItem>`、`<Admonition>` |
| 产品过滤标签 | 页面目录中的图片文件（报 `TRANSFORM_CONTENT_MARKUP`，提示改用外部图片地址） |

文件必须在 `page.yaml` 所在目录中，不能用 `..` 或符号链接逃出去（`TRANSFORM_CONTENT_NOT_FOUND`）。Fetch 的记录文件本来就列出 `shared-docs/guides/` 下的全部文件，内容文件自动包括在内，测试中确认过。

### 5. `channel`

`channel: current` 只在第一遍执行，`channel: next` 只在第二遍执行，不带的两遍都执行。两遍的结果不同时，WP10 仍报 “two-version merging requires WP11”，合并留给 WP11。

## 刻意没做的

- **两版合并**：两遍结果不同时仍报错，WP11 做。
- **提升时清理 `channel` 规则**：WP13。
- **页面目录中的图片**：报错，提示改用外部图片地址。
- **`shared-docs inspect` 显示变换后的内容**：它仍只看原文，README 中说明。
- **句子级的变换**：见[技术设计 02 的设计理由](../../design/02-page-config.md#设计理由)。
- **自动增加语言**：只做配置中明确写了的 `add`。

## 已知的问题

- **删除命名块后多一个空行。** 删除时去掉了块与标记，块前后的空行都留下来，MDX 中出现两个连续的空行（产品需求 4-3 要求不留多余空行）；渲染不受影响。第三批接入时发现，由 WP9b-1 修复（[liyun95/zdoc#16](https://github.com/liyun95/zdoc/pull/16)）。
- **每个手册各预处理一遍**（zdoc 文档负责人审阅时的 P2 #2）、**`dedent` 以第一行而不是第一个非空行为基准**（P2 #3）：都在 [WP11](./WP11.md) 中修复。
